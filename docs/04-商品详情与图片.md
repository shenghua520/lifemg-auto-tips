# 04 · 商品详情与图片

## 详情页路由

从 Vue Router 里读出来的路由表（`router.getRoutes()`）：

```
/                       Home
/search-list            SearchList
/goods-list             GoodsList
/goods-detail           GoodsDetail      ← 商品详情
/cart                   Cart
/order                  Order
/often-buy-list         OftenBuyList
/pcadmin/dashboard      AdminDashboard
```

正确写法：

```
✅ https://lifemg.cn/goods-detail?itemId=66496
❌ https://lifemg.cn/items/66496/          → 白屏
❌ https://lifemg.cn/goods-detail?id=66496 → 空壳，只有"商品详情"面包屑
❌ https://lifemg.cn/goods-detail/66496    → 完全空白
```

> 搜索结果里的 `link_url` 是 `https://lifemg.cn/items/66496/?from=0`，
> 那是**移动端/H5 的分享链接**，PC 端直接打开是白屏。
> 判断方法：打开后 `document.images` 长度为 0、没有任何 `/v4/item/` 请求。

### ② 图文详情（详情图的唯一来源）

```
GET /v4/h5/item/{item_id}
```

```json
{
  "data": {
    "detailHtml": "<p><img src=\"…/298edf9d….png\" /></p><p><img src=\"…/9619c769….png\" /></p>",
    "itemDetailDTO": { … },
```

**详情图只在这里**——`detailHtml` 里一串 `<img>`，用正则提取即可。

## 三类图片的取值规则

| 类别 | 字段 | 实测条数 | 备注 |
|------|------|---------|------|
| 主图 | `newDetail.thum_image_url` | 1 | 与 `share_image` 相同，去重后 1 张 |
| 轮播图 | `newDetail.cover_image_url_list[].url` | 7 | `type:1` 是图片；**第 1 张就是主图** |
| 详情图 | `h5.detailHtml` 里的 `<img src>` | 2 | 长图 800×3889 / 800×3866 |
| SKU图 | 搜索接口 `itemSkuList[].coverImageUrl` | 0 | 本商品为空，多数商品都没配 |

`lib/exporter.js` 的 `collectImages()` 负责这块，返回 `{main, carousel, desc, sku}`，每类都 `uniq` 去重。

## 落盘命名与顺序

**一个商品一个目录，所有图片平铺，不建子目录。** 文件名 = `序号_类型.png`：

```
<商品名称>/
├── 01_主图.png
├── 02_轮播图.png
├── 03_轮播图.png
├── …
├── 08_轮播图.png
├── 09_详情图.png
├── 10_详情图.png
├── 11_SKU图_HQKP3043A_6944041509433.png    # 有 SKU 图才有
├── 图片清单.csv
└── 商品信息.json
```

- **按文件名排序 = 页面从上到下的完整顺序**：主图 → 轮播 1..N → 详情 1..N → SKU 图
- 序号是全局连续的两位数，不是每类从 1 开始
- 类型直接写在名字里，不用打开图就知道哪张是主图、哪张是详情图

| 类别 | 序号含义 | 依据 |
|------|---------|------|
| 主图 | 固定第 1 张 | `thum_image_url` |
| 轮播图 | **详情页轮播的左右翻页顺序** | `cover_image_url_list` 数组顺序 |
| 详情图 | **详情页自上而下的顺序** | `detailHtml` 里 `<img>` 出现顺序 |
| SKU图 | 排在最后，名字带 SKU 货号 + 条码 | `itemSkuList[].goodNo` / `goodsBarcode` |

> ⚠️ **`01_主图.png` 与 `02_轮播图.png` 是同一张图**（实测 URL 与字节数一致，472719 B）。
> 这个后台的主图定义就是轮播第一张。要去重就删 `01_主图.png`，Excel 里主图数减 1。

## SKU 图：多数商品没有

这是最容易误解的一块，明确结论：

1. `newDetail.sku_list[]` 里**没有任何图片字段**（只有条码、规格、价格、库存）
2. 详情页也不渲染规格小图（`document.images` 里只有 7 张轮播 + 2 张详情 + 若干 icon）
3. 唯一可能带 SKU 图的是**搜索接口**的 `itemSkuList[].coverImageUrl`，结构上有这个字段，
   但本例 3 个 SKU 全是空字符串

所以脚本的做法是：

```js
for (const s of (searchItem.itemSkuList || [])) {
  if (!s.coverImageUrl) continue;      // 空就跳过
  sku.push({ url: s.coverImageUrl, goodNo: s.goodNo, barcode: s.goodsBarcode });
}
```

有图就落成 `11_SKU图_HQKP3043A_6944041509433.png`（序号接在详情图后面）；没图就没有这个文件，
Excel 里 `SKU图数=0`、`SKU图文件` 为空。

> 判断某个商品到底有没有 SKU 图，跑 `node scripts/99-check-sku-img.js <itemId>`
> 看 `urls.sku.length` 即可，别靠猜。

## 图片存储

CDN 直链公开可下：

```
https://qiniupic-ssl.lifemg.cn/image/<32位hash>.png
```

- 无签名、无防盗链，但带上 `Referer: https://lifemg.cn/` 更稳
- 扩展名从 URL 尾巴推，推不出默认 `.png`
- 文件名按序号 `01.png / 02.png …`，序号即接口返回顺序（= 页面展示顺序）

```js
const res = await ctx.request.get(url, { headers: { referer: 'https://lifemg.cn/' } });
fs.writeFileSync(dest, await res.body());
```

## SKU 字段有个前缀陷阱

`newDetail.sku_list[]` 里这几个字段是**给页面直接渲染的展示字符串**，带前缀：

| 字段 | 实际值 | 需要的前缀剥离 |
|------|--------|---------------|
| `barCode` | `条码: 6944041509433` | `条码:` |
| `skuCode` | `编码: 60096547` | `编码:` |
| `moqText` | `起订量: 1PCS` | `起订量:` |
| `packUnitString` | `规格: 1/20/900` | `规格:` |

直接写进 Excel 会变成"条码: 6944…"，看起来很脏。`exporter.js` 里 `stripPrefix()` 处理。

干净的对应字段：

- 条码 → `barCode` 去前缀
- SKU 货号 → `goodNo`（如 `HQKP3043A`）
- 规格 → `prop_value`（如 `黑0.5`，这个没有前缀）
- 包装 → `skuUnit[]`（`[{count:'1',name:'PCS'}, {count:'20',name:'小盒'}, {count:'900',name:'箱'}]`）
