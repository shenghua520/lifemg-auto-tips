# 06 · 踩坑与事故复盘 🔴

按"卡了多久"排序，前三个是真把人绕晕的。

---

## 1. 不选门店 → 搜索恒返回 0 条，且不报错

**现象**：条码搜不到，换成"中性笔""圆规"也搜不到。接口 `code: 0`、`message: 请求成功`。

**误判过程**：先怀疑参数名 → 试了 `keyword` / `keywords` / `key`，全部 `code: 500 未知错误`（说明 `keyWords` 才是对的）；
再怀疑 `openSearchRequestId` → 从 hintSearch 拿到 requestId 塞进去，还是 0；
再怀疑 queryType → 1~5 全试，还是 0。

**真相**：请求头里 `auth_storeid: 0`、`auth_org_code: 未绑定终端`。账号没在当前会话选门店，搜索索引为空。

**修复**：`POST /v4/users/shop`（form-data `shop_id`）+ 写 `localStorage.storeId`，刷新页面。

**教训**：
> 接口返回"成功但空列表"时，先查**上下文参数**（门店/仓库/组织），别先怀疑参数名。
> 空列表 + code 0 是"权限/上下文不满足"的经典伪装。

## 2. 搜索参数大小写：`keyWords` 不是 `keyword`

**现象**：访问 `/search-list?keyword=6944041509433`，页面正常打开，搜索框空着，显示"暂无相关商品"。

**真相**：前端路由读的是 `?keyWords=`。参数名不对时**不报错、不提示**，组件就用空值去搜。

**验证方法**：抓真实请求。在结果页的搜索框（placeholder `请输入搜索内容`）里手输一次并回车，
看到 URL 变成 `/search-list?keyWords=6944041509433`，请求里 `keyWords=6944041509433` 才恍然大悟。

**教训**：
> SPA 路由参数名只能靠抓包确认，不能靠猜。
> 猜错的表现通常是"静默降级"，比报错更难查。

## 3. 拿到的 `link_url` 在 PC 端白屏

**现象**：搜索返回 `link_url: https://lifemg.cn/items/66496/?from=0`，Playwright 打开是纯白页，
`document.images.length === 0`，没有 `/v4/item/` 请求。

**真相**：`/items/<id>/` 是 H5/分享链接，PC 端路由表里没有这条。
PC 详情路由是 `/goods-detail`，参数 `itemId`。

```js
// 从 Vue Router 直接路由表，比猜快
const router = document.querySelector('#app').__vue_app__.config.globalProperties.$router;
router.getRoutes().map(r => r.path);
```

**教训**：
> 接口里的 `link_url` / `share_url` / `detail_url` 不一定是当前端能用的地址。
> 白屏不是"页面坏了"，多半是路由不匹配。

## 4. Element Plus 复选框点不动

**现象**：`locator('input[type=checkbox]').check()` 报 `Element is not visible`；
`check({force:true})` 也不一定改到 Vue 的 `v-model`；
不勾选就点登录 → 提示"请勾选同意协议"，登录请求根本不发。

**真相**：`input.el-checkbox__original` 是 `opacity: 0` 的隐藏元素，Element Plus 靠点 `<label>` 触发。

```js
await page.evaluate(() => {
  const lbl = document.querySelector('.agree .el-checkbox');
  if (lbl && !lbl.className.includes('is-checked')) lbl.click();
});
// 成功标志：label 的 class 里出现 is-checked
```

## 5. 登录按钮被 footer 拦截

**现象**：`click()` 一直重试直到 30s 超时：

```
<div class="footer"> … subtree intercepts pointer events
```

**修复**：`click({ force: true })`；同时把 viewport 设成 1600×1000 减少遮挡。

## 6. 密码末尾的句点

密码少写结尾的句点 → `412 手机号或密码错误`；把句点补上 → 成功。

给口令时句末的 `.` / `。` 到底算不算密码，**先原样试一次**。
这次就是靠原样试中的。写进 `config.local.js` 时也别"顺手清理"。

## 7. 手搓 fetch 不带鉴权头 → 全是空结果

**现象**：`page.evaluate(fetch('/v4/search/searchGoodsV2?...'))` 返回 `code: 0` 但 `secondItems: []`，
而页面上明明有商品。

**真相**：前端 axios 拦截器注入了 `pctoken` / `auth_storeid` / `shopid` / `auth_org_code` 等 9 个头。
裸 `fetch` 只带 Cookie，接口不报错、就是不给数据。

**修复**：`lib/common.js → api()` 从 localStorage 重建这套头再发请求。

**教训**：
> "浏览器里能出数据、脚本里出不来" → 十有八九是请求头缺了。
> 排查方式：`page.on('request')` 打一次真实请求的 headers，逐项对齐。

## 8. 详情图别从 DOM 抓

**现象**：滚动到底再取 `document.images`，详情图数量时多时少，甚至 0 张。

**真相**：图文详情的图是懒加载 + 富文本渲染，滚动速度、视口、虚拟列表都会影响 DOM。
但接口 `GET /v4/h5/item/{id}` 的 `detailHtml` 里，`<img>` 是**完整且稳定**的。

**教训**：
> 能走接口就别解析 DOM。DOM 是渲染结果，接口才是数据源。

## 9. 首屏 hydration 竞态：第一次登录必失败

**现象**：冷启动时第一次登录一定停在登录页，第二次（同进程内重试）就成功。非常规律。

**原因**：SPA 首屏 JS 还在加载时，`input` 元素已经渲染出来了（SSR 占位/骨架），
但 Vue 还没挂载。此时 `page.fill()` 写进去的值，会在 Vue mounted 用空 state 覆盖掉，
于是提交时密码是空的 → `412 手机号或密码错误`（或提示"请勾选同意协议"，因为勾选同样被覆盖）。

**修复**（`lib/common.js → login()`）：

1. `waitForLoadState('networkidle')` 再动手，别只等 `domcontentloaded`
2. **填完回读校验**，`input.value` 不等于目标值就重填，最多 5 次
3. 勾选后确认 `label.className` 含 `is-checked`，不含就再点
4. 整体重试 3 轮，失败时打印 `pwd_signin` 的 `code/message`，别只打印页面文字

```js
await page.waitForLoadState('networkidle');
for (let k = 0; k < 5; k++) {
  await page.fill(sel.phone, cfg.phone);
  await page.fill(sel.pwd, cfg.password);
  const v = await page.evaluate(...);   // 回读
  if (v.phone === cfg.phone && v.pwd === cfg.password) break;
  await sleep(600);
}
```

**教训**：
> 对 SPA，`domcontentloaded` 只代表 HTML 到了，不代表框架挂载完。
> 凡是"第一次不行、第二次行"，基本都是竞态，用**回读校验**兜底最省事。

## 附：门店列表字段是 `data.items`

`GET /v4/users/newShopList` 返回 `data.items`，不是 `data.list` / `data.records`。
按 `data.list` 解析会得到"没有可选门店"，然后去怀疑账号权限——白绕一圈。

本站 `/v4/**` 的列表接口基本都是 `data.items` + `data.total` + `data.hasNext`。

---

## 一句话总结

> **接口"成功但为空"先查上下文（门店/组织），再查参数大小写。**
> **路由和参数名一律靠抓包确认，别猜。**
> **能调接口就别点 UI，能解析接口就别解析 DOM。**
