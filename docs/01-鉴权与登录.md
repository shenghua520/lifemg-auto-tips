# 01 · 鉴权与登录

## 登录接口

```
POST https://lifemg.cn/v4/account/pwd_signin/pc
Content-Type: application/json（前端 axios 默认）

{ "mobile": "<PHONE>", "password": "<PASSWORD>" }
```

成功响应（节选）：

```json
{
  "code": 200,
  "success": true,
  "data": {
    "id": <USER_ID>,
    "mobile": "<PHONE>",
    "nickname": "<STORE_NAME>",
    "pcToken": "eyJhbGciOiJIUzI1NiJ9...",
    "adminIdentity": 1,
    "deliver_code": "<DELIVER_CODE>",
    "deliver_name": "<DELIVER_NAME>",
    "has_shop_selected": true,
    "shop_selected": { "shop_code": "<SHOP_CODE>", "store_id": <STORE_ID>, "store": "<STORE_NAME>" }
  }
}
```

失败：

```json
{ "code": 412, "message": "手机号或密码错误", "success": false }
```

> ⚠️ `has_shop_selected: true` **不代表**当次会话可用，见 [02 · 门店选择](02-门店选择-shop.md)。

## 三个登录坑

### 1. 密码结尾可能带标点

密码少写结尾的句点 → `412 手机号或密码错误`；把句点补上 → `200 成功`。
密码里有 `.` `,` `。` 这类尾巴时，**先原样试一次**，再去掉试。

### 2. 协议勾选框必须点 label

页面结构：

```html
<label class="el-checkbox">
  <span class="el-checkbox__input"><input type="checkbox"></span>
  <span class="el-checkbox__label">我已经阅读并同意…</span>
</label>
```

`input[type=checkbox]` 是 `opacity:0` 的隐藏元素，Playwright 点它会报
`Element is not visible`；`check({force:true})` 也可能改不到 Vue 的 `v-model`。
**正确做法是点 `label`**：

```js
await page.evaluate(() => {
  const lbl = document.querySelector('.agree .el-checkbox');
  if (lbl && !lbl.className.includes('is-checked')) lbl.click();
});
// 校验：class 里出现 is-checked 才算成功
```

不勾会提示"请勾选同意协议"，且不发登录请求。

### 3. 登录按钮会被 footer 遮挡

按钮本身 `visible/stable`，但底部 `.footer` 覆盖了点击位置，Playwright 会一直重试直到超时：

```
<div class="footer"> … subtree intercepts pointer events
```

解决：`click({ force: true })`，或把 viewport 调高到 1600×1000。

### 4. 首屏 hydration 竞态（"第一次必失败、第二次就好"）

冷启动时 `input` 已渲染但 Vue 未挂载，`fill()` 写进去的值会被 mounted 后的空 state 覆盖，
提交时密码为空 → `412`。所以 `login()` 必须：

```js
await page.waitForLoadState('networkidle');     // 别只等 domcontentloaded
// 填完回读 input.value，不等于目标值就重填（最多 5 次）
// 勾选后确认 class 含 is-checked
// 整体重试 3 轮，失败时打印 pwd_signin 的 code/message
```

详见 [06 · 踩坑](06-踩坑与事故复盘.md#9-首屏-hydration-竞态第一次登录必失败)。

## 登录态怎么存

关键只有两项：

- **Cookie**：`acw_tc`（阿里云 WAF）等，靠 `context.storageState()` 一起存
- **localStorage**：`pcToken`、`user`、`storeId`、`cart`

```js
await ctx.storageState({ path: 'profile/auth.json' });   // 存
const ctx = await browser.newContext({ storageState: 'profile/auth.json' });  // 复用
```

`profile/` 已在 `.gitignore`，不会进版本库。

## 接口鉴权：9 个请求头

前端用 axios 拦截器统一注入。**光有 Cookie 不够**，手搓 `fetch` 时必须自己补齐，否则接口一律返回空数据（`code:0`，不报错）。

| Header | 取值来源 | 说明 |
|--------|---------|------|
| `pctoken` | `localStorage.pcToken` | PC 端 JWT，最关键 |
| `newh5token` | `user.userInfo.newH5Token` | H5 端 JWT |
| `auth_userid` | `user.userInfo.id` | 用户 ID |
| `auth_storeid` | `localStorage.storeId` | 🔴 门店 ID，`0` = 未选门店 |
| `shopid` | 同 `auth_storeid` | 同上 |
| `auth_shop_code` | `user.userInfo.storeCode` | 门店编码，如 `<SHOP_CODE>` |
| `auth_org_code` | `user.userInfo.store`（URL 编码） | 未选门店时是 `未绑定终端` |
| `auth_user_org_code` | `user.userInfo.deliver_code` | 配送中心编码 `<DELIVER_CODE>` |
| `auth_username` | `user.userInfo.nickname`（URL 编码） | 用户名 |

另有固定值：`mgchannel: pc`、`x-ver: 9.8.27`、`x-app: cn.lifemg.union`、`x-os: iOS`、`x-os1: iOS`、`x-build: 1`、`accept: application/json, text/plain, */*`。

`lib/common.js` 的 `api()` 就是把上面这套头拼好再 `page.evaluate(fetch)`，好处是自动带 Cookie 和同源，不用管 CORS。

## 令牌有效期

`pcToken` 是 JWT，`exp` 约 1 年后（实测 `1824701515`）。正常不会中途失效；失效表现为接口 `code` 非 0 或跳登录页，此时重跑 `00-login-save-state.js` 即可。
